# 🎯 dartboard

**DART 공시를 읽고, 모든 판단에 성적표를 남기는 투자 리서치 에이전트**

이름은 두 가지 뜻입니다. 금융감독원 전자공시 시스템 **DART**를 읽는 **보드**이고, 다트판처럼 판단이 과녁에 맞았는지 하나하나 기록하는 **점수판**입니다.

> 수익을 "내는" AI가 아니라 수익을 **"검증하는"** AI를 만듭니다.
> LLM이 예측한 수익률은 과거 데이터에서 부풀려지기 쉽습니다(미래 정보 누출). 그래서 이 프로젝트는 모든 판단을 만들어진 순간에 고정해 기록하고, 시간이 지난 뒤 시장 대비로 채점합니다.

## 무엇을 하나

1. **판단 대상**: 유가증권·코스닥 상장사 전체의 주요사항보고서·수시공시·공정공시를 봅니다. 주주총회·IR 안내 같은 행정 공지와 스팩은 건너뜁니다. 정정·철회 같은 후속 공시도 판단해 기록하지만 공식 채점에는 넣지 않습니다.
2. **판단**: AI가 공시 원문을 읽고 요약과 함께 "5거래일 동안 이 종목이 기준 지수(코스피 또는 코스닥)보다 더 오를 확률"을 냅니다. 관심 종목은 Discord로 알리고, 나머지 종목은 집 PC의 모델로만 판단해 성적표에만 남깁니다.
3. **숫자 검증**: 요약 속 숫자가 공시 원문에 실제로 있는지 확인합니다. 관심 종목에서 원문에 없는 숫자가 나오면 Discord로 사람에게 묻고, 그 결정을 판단과 따로 기록합니다.
4. **성적표**: 판단·사람의 결정·채점 결과를 한 줄씩 쌓는 기록입니다. DB가 수정·삭제 명령을 거부하고, 기록마다 앞 기록의 해시를 이어 붙여 몰래 고치면 드러나게 했습니다(변조 감지). 파일을 통째로 다시 쓰는 것까지 막지는 못해서, 매일 체인을 검사하고 마지막 해시를 Discord에 남깁니다. 같은 단계가 다시 실행돼도 기록마다 정해진 키가 있어 한 번만 남습니다.
5. **채점**: 정해 둔 규칙으로만 채점합니다(아래 "채점 규칙"). 성적은 늘 50%라고 답하는 기준선과 과거 비율(기저율) 기준선에 견주고, 채점 100건 전에는 참고용으로만 보여 줍니다.

주문 한도·승인 규칙을 담은 정책 엔진(`policy.py`)은 만들어 두었지만 아직 어디에도 연결되지 않았습니다. 주문 기능을 만들 때 연결합니다.

## 구성

```
[데이터]   OpenDART(공시 목록·원문) · KIS Open API(수정주가·지수)
    ↓
[OCI 서버, 24시간]  LangGraph 워크플로 · 성적표 DB · 채점 · Discord 봇
    ↓  Tailscale
[4090 PC]           vLLM + Qwen (OpenAI 호환 API)
    ↓  PC가 꺼져 있으면 1.5초 안에 전환 (관심 종목만)
[클라우드 예비]      Groq → Gemini
```

| 층 | 선택 |
|---|---|
| 모델 | Qwen |
| 추론 엔진 | vLLM (Docker) |
| 에이전트 | LangGraph |
| 알림·승인 | Discord |
| 저장 | SQLite (append-only) |

## 흐름

```
10분마다 (평일 07~21시)   OpenDART에서 주요사항보고서·수시공시·공정공시 목록 (종류마다 따로 조회)
        ↓                 (매번 최근 3일을 훑어 주말·심야 공시와 PC가 꺼져 밀린 공시도 놓치지 않음)
        ↓                 행정 공지·스팩·코넥스는 건너뜀, 정정·철회는 후속 공시로 표시
공시 원문 내려받기 → AI 판단(요약 + 확률) → 숫자 검증 → 성적표에 기록
        ↓ 관심 종목                                   ↓ 나머지 종목
원문에 없는 숫자가 있으면 Discord [승인]/[거절]      기록만 (한 번에 30건씩, 집 PC 모델로만)
→ 사람 결정을 따로 기록 (30분 무응답 = 거절)
→ Discord 알림
        ↓
매일 18:30   기간이 끝난 예측을 KRX 정규장 가격으로 채점 → 거래일 대조 → 해시 체인 검사 → 끝 해시와 성적을 Discord에 게시
             → 백업을 만들어 바로 복원 검사 → 백업 파일을 Discord에 첨부 (/report로 언제든 조회)
10분마다     바깥 감시 서비스에 하트비트 (끊기면 그 서비스가 알림)
```

공시 하나가 LangGraph 스레드 하나이고, 단계마다 체크포인트에 저장됩니다. 봇이 중간에 죽거나 Discord 전송이 실패하면 멈춘 단계부터 이어갑니다. 성적표 기록에는 공시마다 정해진 키가 있어서, 기록 직후 죽어 같은 단계가 다시 돌아도 기록은 한 번만 남습니다. 어떤 AI에도 닿지 않으면(집 PC 꺼짐, 예비 AI 한도 초과) 기록하지 않고 다음 실행 때 다시 시도합니다. AI가 답은 했지만 형식에 맞지 않으면 "실패한 판단"으로 기록합니다.

## 채점 규칙

- **진입**: 판단이 기록된 뒤 처음 열리는 정규장의 시가. 시가를 정하는 동시호가가 09:00에 끝나므로 08:50 전에 기록된 판단만 그날 시가로 들어갑니다.
- **청산**: 진입일을 1일째로 세어 5번째 거래일의 정규장 종가. 1·20거래일도 같은 방식으로 참고 기록합니다.
- **가격**: KRX 정규장 시가·종가만 씁니다(애프터마켓·넥스트레이드 가격 제외). 거래일은 기준 지수에 일봉이 있는 날이고, 오늘 일봉은 쓰지 않습니다.
- **공식 채점**: 새 공시(후속 공시 제외)의 5거래일 예측 중, 진입이 "접수일 다음 첫 거래일"보다 늦지 않은 것만. 기간 중 종목 가격이 하루라도 없으면(거래정지 등) "채점 불가"로 기록하고 건수를 따로 보여 줍니다.
- **성적**: Brier 점수(확률과 결과의 차이 제곱 평균)를 늘 50% 기준선과 기저율 기준선에 견줍니다. 95% 신뢰구간은 같은 날 공시를 한 묶음으로 다시 뽑아 계산하고(부트스트랩), 구간 아래 끝이 0보다 커야 "기준선보다 낫다"고 씁니다. 확률이 높을수록 초과수익도 컸는지는 순위 상관(IC)으로 함께 보여 주고, 거래 비용(왕복 약 0.23%)은 "샀다면" 참고 줄에서만 뺍니다.

## 시작하기

```bash
pip install -e ".[dev]"
pytest
```

### 서버(OCI)에서 봇 실행

1. 키 준비. 키는 서버의 `.env`에만 넣습니다.
   - OpenDART 인증키: [opendart.fss.or.kr](https://opendart.fss.or.kr)
   - KIS 앱키·시크릿: [KIS Developers](https://apiportal.koreainvestment.com) (한국투자증권 계좌 필요, 없으면 채점만 꺼짐). 돈과 주식이 없는 계좌의 실전 키를 권장합니다. 모의투자 키로 받은 시세는 빠지거나 부정확할 수 있다고 한국투자가 안내합니다.
   - Discord 봇: [개발자 포털](https://discord.com/developers/applications) → 앱 생성 → **Bot**에서 토큰 발급 → **Installation**에서 Guild Install에 `bot`·`applications.commands` 범위와 `View Channels`·`Send Messages`·`Embed Links` 권한 지정 → 설치 링크로 내 서버에 추가
   - 채널 ID·내 사용자 ID: Discord 설정 → 고급 → 개발자 모드 켜기 → 채널/내 이름 우클릭 → ID 복사
2. 점검한 뒤 실행

```bash
git clone https://github.com/Oilwoo/dartboard && cd dartboard
cp .env.example .env
nano .env
cp watchlist.example.yaml watchlist.yaml   # 실제 종목은 이 파일에만 적습니다(git이 무시함)
nano watchlist.yaml
docker compose build
docker compose run --rm bot python -m dartboard.check   # 외부 서비스마다 최소 호출로 확인, 비밀값은 출력 안 함
docker compose up -d
docker compose logs -f
```

3. 하트비트, 백업, 새 서버로 되살리기는 [docs/operations.md](docs/operations.md)에 있습니다.

집 PC(4090)의 vLLM과 Tailscale 설정 순서는 [docs/home-pc.md](docs/home-pc.md)에 있습니다. vLLM은 기본으로 PC 자신(127.0.0.1)에서만 받고, Tailscale 주소를 지정해야 서버가 닿습니다.

## 원칙

- **본인 계좌 전용.** 타인에게 유료로 종목 신호를 주면 유사투자자문업 신고, 타인 계좌를 자동매매하면 투자일임업 등록 대상입니다.
- **비밀값과 보유 종목은 커밋하지 않습니다.** `.env`, 실제 관심 종목(`watchlist.yaml`), 백업 폴더(`backup/`)는 `.gitignore`에 있습니다.
- **검증 근거**는 [docs/verification.md](docs/verification.md)에 있습니다.
